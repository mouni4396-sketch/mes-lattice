Create Maintenance Plan#

🔒 Maintenance Plan.Create

🔒 Maintenance Plan.CreateTemplate

🔒 Maintenance Plan.CreateFromTemplate

Overview#

This operation is used to create a Maintenance Plan.

Setup#

No specific setup is required other than to meet the preconditions of the transaction.

Preconditions#

  • The Maintenance Plan name must be unique.

Sequence of Steps#

There are several ways to create a new versioned object. Depending on the level, follow these steps to get started:

  • Entity - in the landing page of this entity type in the Business Data menu or in the details page of an existing entity of the same type, select New on the top ribbon. For more information, see Creating Entity Objects.
  • Revision - if you want to create a new revision, go to the New dropdown button on the top ribbon and select Revision. For more information, see Revisions.
  • Version - if you want to create a version associated to an existing revision, go to the New dropdown button on the top ribbon and select Version. For more information, see Versions.

Step 1: Change Set#

  1. Choose an existing Change Set or select Create to create a new Change Set. If configured to support implicit Change Sets, it is also possible to check the Use Automatic Change Set option.
  2. Optionally, select an Approval Role.
  3. Optionally, set the Make Change Set Items Effective on Approval to true so that the Change Set items become effective when the Change Set is approved.

Info

For more information, see Create Change Set.

Step 2: General Data#

  1. Provide a Name for the Maintenance Plan.

  2. If you are creating a new version, the revision that was selected when you started the process will be the revision to which this version will be associated. If you are creating a new entity or revision (with a new version associated to it), provide a name for the revision or it will be automatically generated for you. For more information on revision naming, see Revisions.

  3. Optionally, enter a Description.

  4. Select the Maintenance Plan Type. The list of possible values is taken from the Maintenance Plan Type Lookup Table.

  5. Select the Scope for the Maintenance Plan:

    • Maintenance Management (default)
    • In-Process Verification
    • Qualification - The Maintenance Type is set to Qualification and cannot be changed.

  6. Select Create to complete the operation and the new Maintenance Plan will be created:

At this point the Maintenance Plan is created but there are no Maintenance Activities defined for it. New activities can be added and existing ones can be removed by selecting the or button. Optionally, you can choose to copy activities from another Maintenance Plans:

Step 3: Adding Maintenance Activities#

To create additional activities, start with the button on the top ribbon or in the center of the window. This will show a panel on the left side where you can add the required Maintenance Activities. The details for each activity are listed on the right side panel, under several different tabs:

  1. Enter the Name.
  2. Enter the Description.
  3. Select the Type.

  4. Specify the Schedule Type, which can be:

    • Ad hoc
    • Time Based
    • Usage And Time Based
    • Usage Based

    Info

    Time Based, Usage Based, and Usage And Time Based are scheduled automatically by the system and cannot be terminated manually by the user.

  5. Specify the expected activity duration in hours.

  6. Specify the Execution Role for this activity - this represents the group of people who is authorized/qualified to perform the maintenance task.
  7. For activities of type Ad hoc it is possible to define a Request Role. If defined, only users that belong to this role are able to request this maintenance activity.
  8. For activities of type Ad hoc it is possible to define a lookup table as Root Cause Source that you must specify when closing the Ad hoc Maintenance Activity Order.
  9. Specify whether the approval mode is automatic or manual.

  10. Define the Maintenance Type, which can be:

    • Calibration
    • Corrective
    • Inspection
    • Preventive
    • Qualification

    Info

    The Corrective option for Maintenance Type is only available if the Schedule Type is Ad hoc. If when creating the Maintenance Plan the selected Scope is In-Process Verification, the Maintenance Type property will be set to this Scope and cannot be changed.

  11. Choose the Material Type Restriction Mode. For Maintenance Management, this property defines whether it is still possible to track-in a Material when the Resource is down or on hold for Maintenance (only applicable to Resources of Processing Type equal to Process or Line). The available options by scope are:

    • Maintenance Management:

      • Allow All
      • Allow None
      • Allow Specific - you must specify the allowed Material Type (retrieved from the Material Type Lookup Table).

    • In Process Verification:

      • The Material Type Restriction Mode will be automatically set to Allow All and cannot be changed.

    • Qualification (to be selected on the Qualification tab):

      • Require Specific - you must specify the required Material Type (retrieved from the Material Type Lookup Table).
      • Require None

  12. Specify whether the Maintenance Activity Order release mode is automatic or manual.

  13. Specify whether the acceptance mode is automatic or manual.
  14. For activities of type Time Based, Usage And Time Based, and Usage Based, it is possible to define the Auto Disable After Late Due property. So the entity with which the Maintenance Plan is associated will be put on hold if the value for Late Due is reached while the Maintenance Activity Order is yet to be performed.

  15. If the activity type is Ad hoc, specify whether multiple concurrent instances of the same Ad hoc are allowed for the same Maintenance Plan Instance. If the activity type is Time and/or Usage based, specify whether the Resource (or Container) will automatically be placed on hold if the activity reaches its late due. Putting the entity on hold has the following effects:

    • For Resources, it will not be possible to track-in Materials to the Resource.
    • For Containers, it will not be possible to associate Materials with the Container.

  16. Specify whether the activity must be ignored for Scheduling purposes (more specifically if the Resource must be considered available for Scheduling for the duration of the maintenance).

    Note

    When the Maintenance Plan scope is set to In Process Verification, the Ignore in Scheduling option is automatically set to true and cannot be changed.

  17. Specify a Post Maintenance Activity if the scope is Maintenance Management or Qualification, and select the corresponding Maintenance Plan and Maintenance Activity.

Info

When determining the Calendar to be used, the system executes a specific DEE action (EvaluateCalendarForEntity) that retrieves the Calendar to use depending on the Entity type used. If a custom entity is to be used for the Maintenance Plan, this rule should be altered to accommodate it.

  1. Optionally, enable Auto Begin Qualification (default to true).
  2. Optionally, enable Auto Complete Qualification (default to true). This option is only available when the Type Restriction Mode is set to Require Specific.

Note

When Auto Complete Qualification is enabled, the MAO is automatically completed once all qualification results have been captured - provided the MAO can be closed: Data Collection (if any) is filled, Checklist (if any) is complete, and Parts (if any) are filled.

Time Based / Usage And Time Based

  1. Time due frequency scale:

    • Days
    • Hours
    • Months
    • On Shift Change - provides a way to schedule the Maintenance Activity Order based on the shift of a predetermined Calendar.
    • Weeks

  2. If On Shift Change, you must define the Offset Type:

    • None (default) - no offset is applied to the next shift change.
    • Duration - can define a value between 0 and 100, which is presented as a percentage and is based on the duration of the shift, if defined the Maintenance Activity Order will be scheduled to the next shift start date plus the defined duration.
    • Hours - can define a value between -24 and 24 hours (0.5 indicates 30 minutes), if defined the Maintenance Activity Order will be scheduled to the next shift start date plus the defined hours.

  3. The recurrence details - depending on the time due frequency scale it can define days of the month, day of the week, hour of the day or simply hours. In same cases (Monthly and Weekly or Daily), it is possible also to define the time when the maintenance should be performed.

  4. The early due and late due deltas - depending on the time due frequency scale it can specify days or hours depending on the time due frequency.

Usage Based / Usage And Time Based

  1. Usage Early due - in units
  2. Usage Due - in units
  3. Usage Late Due - in units

  4. Counter type, which can be:

    • CountExpression - use a flexible expression to increase the counter. In this case it is necessary to provide a valid Usage Based Expression (example: $Resource.IncreaseAmount or $Material.Product.ExposureIntensity).
    • CountOne - always increment the counter by one.
    • CountQuantityOne - increment the counter by the primary quantity.
    • CountQuantityTwo - increment the counter by the secondary quantity.

    Info

    For more information, syntax and available options to create custom expressions, see Expression Evaluator.

  5. Counter event, from a pre-defined list of events.

  6. Schedule Next Mode:

    • Dependant
    • Fixed

Time Based / Usage And Time Based

  1. Schedule Mode - which defines the day when the maintenance will be scheduled, and that can be:

    • AnyDay
    • NextWorkingDay
    • PreviousWorkingDay

    Info

    When using NextWorkingDay or PreviousWorkingDay it is necessary to have Calendar Days generated for the appropriate object.

  2. Schedule Next Mode - which defines if the re-scheduling is fixed or dependent on when the activity is being re-scheduled, and that can be:

    • Dependant, the counter and schedule are reset once the MAO is completed.

    • Fixed, the counter and schedule are resumed once the MAO is completed. The configuration setting /Cmf/System/Configuration/MaintenanceManagement/UsageFixedNextMode/ controls the counter and targets behavior for usage based activities:

      • If not defined, the counters are adjusted and the targets remain fixed.
      • If defined as ResetCounters, the counters are reset to zero and the targets are adjusted.

  3. For time based activities for which the schedule next mode is fixed, it is possible to specify a certain number of occurrences to schedule:

Note

These occurrences are scheduled using a sliding window approach.

This tab defines the main execution parameters.

  1. Specify whether the execution is Manual Begin and Complete or Automatic Begin and Complete. When the Begin and Complete Mode is automatic, it is not necessary to perform the Begin and Close Maintenance Activity Order operations, only the Perform Maintenance Activity Order.
  2. Optionally, define a Checklist (must be of scope Maintenance Management) to be performed as part of the normal maintenance. If the Begin and Complete Mode is manual, it is necessary to specify a Checklist to be performed.
  3. Optionally, define a Data Collection to be performed as part of the normal maintenance.
  4. Optionally, define a Data Collection Limit Set to be applied as part of the normal maintenance.
  5. Optionally, define a Checklist (must be of scope Maintenance Management) to be performed as part of rework.
  6. Optionally, define a Data Collection to be performed as part of rework.
  7. Optionally, define a Data Collection Limit Set to be applied as part of rework.

The same integration principles as defined for Integrating EDC with SPC apply. For SPC Chart visualization there are the following different possible modes:

    • AcknowledgeAlways - the Chart is always displayed and must be acknowledged by the user.
    • AcknowledgeOnViolationsOnly - the Chart is only displayed in case that there is a violation and must be acknowledged by the user.
    • DisplayAlways - the Chart is always displayed and but does need to be acknowledged by the user.
    • DisplayOnViolationsOnly - the Chart is only displayed in case that there is a violation but does need to be be acknowledged by the user.
    • None - the Chart is never displayed.

This tab is used to define inclusion relationships for the Maintenance Activity. For example, if a Yearly Maintenance Activity includes a Monthly Maintenance Activity, it is possible to establish this relationship and have the system link them together automatically during runtime. The inclusion mechanism follows these rules:

  • The scope of the Maintenance Plan must not be Qualification.
  • The Maintenance Activities must have the same Schedule Type and must not be Ad hoc.
  • Both the parent and included Maintenance Activities must be in the same Maintenance Plan version.
  • The included Maintenance Activity must have a shorter cycle than the parent Maintenance Activity.
  • There cannot be circular references.
  • Each Maintenance Activity can only have one top-most Maintenance Activity. For example: A includes B and B includes C is valid whereas A includes B and D includes B is invalid.
  • Furthermore, to allow inclusion of one Maintenance Activity in another, the following properties must be identical:
    • Material Type Restriction Mode
    • Material Type
    • Required Material Product
    • Required Material Flow
    • Required Material Flow Path
    • Required Material Logical Flow Path
    • Required Material Step
    • Qualification Service
    • Post Maintenance Activity Qualification
    • Requires Evaluation
    • Material Evaluation Flow
    • Material Evaluation Flow Path
    • Material Evaluation Logical Path
    • Material Evaluation Step
    • Material Evaluation Results Capture Mode

  1. Add or remove as many Maintenance Activities as desired, selecting the option Join Automatically if you want the system to automatically join the two MAOs whenever their schedule overlap (as determined by the early due - late due interval):

    Info

    It is always possible to manually join or separate MAOs at a later stage.

Warning

After creating a version, it changes to the Created state. To make it Active, the associated Change Set must be approved. To make it Effective, the version must be Set Effective.
